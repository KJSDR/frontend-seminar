DX Comparison — Vanilla JS  ·  React + Zustand  ·  Svelte 5

"The real overhead isn't the bundle. It's the mental model."

Vanilla JS 24 lines 
function render() {
  listEl.innerHTML = state.todos
    .map(t => buildTodoHTML(t))
    .join('')
}

function addTodo(text) {
  state.todos.push({ id: Date.now(), text, done: false })
  render()
  saveState()
}

function deleteTodo(id) {
  state.todos = state.todos.filter(t => t.id !== id)
  render()
  saveState()
}

function toggleTodo(id) {
  const todo = state.todos.find(t => t.id === id)
  if (todo) todo.done = !todo.done
  render()
  saveState()
}
3 responsibilities per action Every mutation: update state, call render(), call saveState(). Miss one = silent bug.
render() required by you Framework handles this for free in React and Svelte. Here you write and maintain it.
React + Zustand 16 lines 
const useStore = create(persist(
  (set) => ({
    todos: [],
    addTodo: (text) => set((s) => ({
      todos: [...s.todos,
        { id: Date.now(), text, done: false }]
    })),
    deleteTodo: (id) => set((s) => ({
      todos: s.todos.filter(t => t.id !== id)
    })),
    toggleTodo: (id) => set((s) => ({
      todos: s.todos.map(t =>
        t.id === id ? { ...t, done: !t.done } : t)
    }))
  }),
  { name: 'todos' }
))
set() handles re-render and storage No manual calls. Define the new state value — Zustand does the rest.
Immutable updates required Can't push or splice directly — must spread arrays and objects every time.
Svelte 5 16 lines 
let todos = $state([])

$effect(() => {
  localStorage.setItem('todos', JSON.stringify(todos))
})

const addTodo = (text) =>
  todos.push({ id: Date.now(), text, done: false })

const deleteTodo = (id) =>
  todos.splice(todos.findIndex(t => t.id === id), 1)

const toggleTodo = (id) => {
  const t = todos.find(t => t.id === id)
  if (t) t.done = !t.done
}
Mutate directly Push, splice, assign — normal JS. No render(), no set(), no spread.
$effect handles storage once Defined once, reacts to every future mutation automatically.
Takeaway
Line counts are similar here — the real difference is coordination burden. Vanilla requires 2 manual calls after every single action. React removes them but forces immutable updates. Svelte lets you mutate like normal JS and reacts automatically. Same browser output across all three.
Vanilla JS 21 lines 
const state = { todos: loadState() }

function loadState() {
  try {
    const raw = localStorage.getItem('todos')
    return raw ? JSON.parse(raw) : []
  } catch {
    return []
  }
}

function saveState() {
  try {
    localStorage.setItem(
      'todos',
      JSON.stringify(state.todos)
    )
  } catch (e) {
    console.error('Failed to persist', e)
  }
}
21 lines, written from scratch Serialization, deserialization, error handling, storage key — every project, every time.
Called manually after every mutation Not automatic. One missed saveState() = silent data loss on refresh.
React + Zustand 4 lines 
create(persist(
  (set) => ({ todos: [] }),
  { name: 'todos' }
))
4 lines of config Handles read on mount, write on change, JSON serialization, and error recovery.
Fully automatic Any state change persists immediately. Nothing to call, nothing to forget.
Svelte 5 9 lines 
let todos = $state(
  JSON.parse(
    localStorage.getItem('todos') ?? '[]'
  )
)

$effect(() => {
  localStorage.setItem('todos',
    JSON.stringify(todos))
})
9 lines, no library $effect reacts to todos automatically. No middleware, no config.
No built-in error recovery Corrupted storage needs manual handling — trade-off for zero dependencies.
Takeaway
21 lines vs 4 lines — same behaviour in the browser. This is the starkest example. Vanilla persistence is boilerplate written from scratch and called manually on every mutation. Zustand collapses it to a single middleware call with automatic sync and error recovery built in.
Vanilla JS 7 lines 
function render() {
  const remaining = state.todos
    .filter(t => !t.done).length

  countEl.textContent = `${remaining} left`
  listEl.innerHTML = buildListHTML(state.todos)
}
Buried inside render() Recalculates on every render — even when unrelated state changed. No isolation, no memoization.
Not reusable Tied to the render function. Can't extract or test independently.
React + useMemo 4 lines 
const remaining = useMemo(
  () => todos.filter(t => !t.done).length,
  [todos]
)
Memoized — skips if deps unchanged Only recalculates when todos changes. Correct when deps are correct.
Manual dependency array Wrong deps = stale count. React can't verify this at compile time.
Svelte 5 3 lines 
let remaining = $derived(
  todos.filter(t => !t.done).length
)
No dependency array Compiler tracks todos at build time. Nothing to get wrong.
Works outside components Unlike Svelte 4, $derived works in plain .js files too.
Takeaway
Vanilla has no concept of derived values — everything recalculates inside render(). React adds memoization but requires a manual dependency array. Svelte 5 removes the problem at the compiler level — $derived tracks its own dependencies automatically, always correct.
